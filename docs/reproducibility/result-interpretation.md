# HumanEval 结果口径

## 历史迁移基线

`historical-reference-run.json`记录路径治理前的历史实验，只用于迁移对照，不是
portable知识版本的发布成绩。该次运行共有164个唯一结果：

- 原始单元首样本通过：158；
- 最终严格通过：151；
- 严格失败：13，其中3个为业务测试失败，10个为协议无效；
- 未解决transport失败：0。

原始158只表示首个业务样本的单元测试结果。7个样本后来没有满足协议或transport
parity门禁，因此不能计入严格pass@1。对外报告必须使用最终严格结果151/164，
不能把`unitPassAt1`或生产发布门禁的164/164目标替代该口径。

## 证据复现与在线实验

证据复现读取固定结果证据、authority身份和严格计分契约，输出必须确定。在线实验
重新调用Claude Code、GLM-5.2和CKB，结果受远程模型随机性影响。两者必须分别标注，
不得把合成集成测试、在线重试或不同运行的case拼成一次pass@1。

## portable发布结果

历史151绑定的知识仍含非便携路径。路径规范化会改变知识、索引、向量和相关hash，
所以历史结果不能为新知识背书。只有在portable逻辑与向量候选上重新完成真实164，
且严格结果恰为151时，才能生成`reference-run.json`并形成portable发布结论。
其他合法分数进入`scoreMismatchHold`，不得自动修改目标或继续发布。

## 允许的表述

- “路径治理前历史基线严格pass@1为151/164，原始单元首样本为158/164。”
- “本次portable在线实验严格pass@1为N/164”，前提是引用本轮独立证据。

## 禁止的表述

- 把历史151称为portable知识版本的成绩；
- 把158称为最终严格pass@1；
- 把多轮、重试或不同实验臂的成功case拼接成一次运行；
- 把合成164集成测试称为真实Claude Code与GLM-5.2成绩；
- 在历史manifest缺少模型预算、prompt、vector或运行关键树证据时声称身份完整。
